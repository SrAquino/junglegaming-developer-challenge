# Optimized-build performance evidence

Measured on 2026-09-16 with the production bundle generated by `npm run build` and served by `npm run preview -- --host 127.0.0.1 --port 4173`. The measurement uses Playwright 1.63.0's bundled headless Chromium at 1440x900 CSS pixels and device-pixel ratio 1. The sandbox does not permit querying the host CPU, GPU or RAM model, so those details are intentionally recorded as unavailable rather than inferred.

Run the measurement with:

```bash
npm run test:performance
```

`optimized-build.spec.ts` drives the actual Pixi canvas for 180 seconds, samples `requestAnimationFrame` intervals and reads the simulation's rendered entity observations once per second. The profile uses the documented 180-second duration, a 20-second spawn interval and continuous forward/right input. The `performance-profile=1` query flag raises only player hull to 100,000 so enemy damage cannot terminate the measurement before the required duration; production gameplay does not use this flag.

## Results

| Measure | Observed value |
| --- | ---: |
| Match duration | 180,010.4 ms |
| Average frame rate | 34.7 FPS |
| Frame-interval p95 | 33.4 ms |
| Maximum enemies | 5 |
| Maximum projectiles | 4 |
| Maximum effects | 2 |

The 60 FPS target was not reached in this headless automated environment. A prior standard-hull attempt ended through normal combat at 71.4 seconds, so it was not used as the three-minute result. The profile result demonstrates that the match completed without ending early; it does not claim performance on a user GPU or a deployed Vercel runtime.

## Resource cycles

Five start/play/exit cycles in one loaded page recorded `JSHeapUsedSize` values of 9,029,340; 9,856,600; 9,633,516; 10,443,908; and 10,522,992 bytes. The fifth measurement is higher than the first, so this run requires follow-up profiling after the map/audio redesign; it does not establish a leak by itself. This is a short diagnostic, not a replacement for a browser heap snapshot or manual GPU-memory profiling on target hardware.

The raw measurements are versioned in `optimized-build-measurement.json` and `resource-cycle-memory.json`.
